# WU-004 — Balanced-v1 Motion-to-Synthetic-Audio Contract

## Scope

WU-004 implements the first deterministic mapping from accepted WU-003 `MotionFeatures` to the accepted WU-001 `SyntheticAudioFrame`. The mapping library is `lib/WledImuUdpMapping`; it depends on the motion and protocol libraries but contains no Arduino, Wi-Fi, UDP, IMU-driver or LED dependency.

This document locks the **Balanced-v1** semantic baseline. These values are a deterministic engineering baseline for later physical tuning, not a claim that they are optimal for every stock WLED Audio Reactive effect.

## Profile identity

- profile enum: `MappingProfile::kBalancedV1`
- profile contract version: `1`
- mapper class: `SyntheticAudioMapper`
- configuration: `MappingConfig`

Materially changing the meaning of the bands or frame fields requires either a profile-version change or an explicit compatibility decision backed by trace and physical evidence.

## Frame-level semantics

Balanced-v1 emits:

- `sampleRaw = clamp(motion_energy_instant × 72, 0, 255)`;
- `sampleSmth = clamp(motion_energy_smoothed × 72, 0, 255)`;
- `samplePeak = true` only on the rising edge of the WU-003 accepted impact latch;
- 16 synthetic spectrum bands, each bounded to `0..254`;
- `FFT_Magnitude` as RMS amplitude of the 16 emitted band values;
- `FFT_MajorPeak` as the band-amplitude-weighted centroid of the locked center table below;
- quiet `FFT_MajorPeak = 1.0` when all spectrum bands are zero.

An invalid `MotionFeatures` snapshot does not advance mapper state. The mapper preserves the last accepted frame but suppresses `samplePeak`, preventing an invalid input from manufacturing or retriggering a peak.

## Four semantic spectrum groups

Balanced-v1 allocates four bands to each motion class:

| Bands | Semantic source | Default full scale | Gain |
|---|---|---:|---:|
| 0–3 | linear/translational acceleration | `0.22 g` | `1.00` |
| 4–7 | angular/rotational speed | `120 dps` | `0.95` |
| 8–11 | jerk/shake activity | `18 g/s` | `0.90` |
| 12–15 | impact/transient activity | impact latch + shake crossfeed | `1.00` |

Each continuous input is normalised to `0..1` at its configured full-scale value. The impact group receives the accepted impact latch plus `0.20 ×` normalised shake as crossfeed, bounded to `0..1`, so sharp broadband movement can energise the high group without generating `samplePeak` unless WU-003 actually detected an impact.

## Orientation shaping

Orientation is a **shape control, never an energy source**.

Within every active four-band group, Balanced-v1 calculates a position bias from:

`orientation.x × 0.75 + orientation.y × 0.25`

The result is clamped to `-1..1`, multiplied by the default orientation-bias strength `0.65`, and used to shift a smooth four-band triangular distribution left or right. The distribution is normalised so its maximum weight remains 1.0.

Consequences locked by tests:

- equal motion energy at opposite tilts produces equal `sampleRaw`/`sampleSmth`;
- existing spectral energy moves coherently across nearby bands;
- static tilted input converges to the same zero spectrum and zero level as static level input.

## Canonical center table

`FFT_MajorPeak` uses these synthetic frequency-like centers, in Hz-like WLED units:

| Band | Center |
|---:|---:|
| 0 | 65 |
| 1 | 92 |
| 2 | 131 |
| 3 | 185 |
| 4 | 262 |
| 5 | 370 |
| 6 | 523 |
| 7 | 740 |
| 8 | 1047 |
| 9 | 1480 |
| 10 | 2093 |
| 11 | 2960 |
| 12 | 4186 |
| 13 | 5920 |
| 14 | 8372 |
| 15 | 11840 |

For non-zero spectrum:

`major_peak = sum(band[i] × center[i]) / sum(band[i])`

This is intentionally a synthetic descriptor, not an acoustic FFT frequency estimate.

## Default `MappingConfig`

- level gain: `72.0`
- translation full scale: `0.22 g`
- rotation full scale: `120 dps`
- shake full scale: `18 g/s`
- translation band gain: `1.00`
- rotation band gain: `0.95`
- shake band gain: `0.90`
- impact band gain: `1.00`
- shake→impact crossfeed: `0.20`
- orientation bias strength: `0.65`
- quiet major peak: `1.0`

Configuration changes are deterministic and do not modify the packet ABI.

## Host inspection tool

The native `mapping_probe` target exposes representative semantic snapshots without IMU hardware or network access:

```text
wledimuudp-mapper <still|sway|spin|shake|impact|tilt-left|tilt-right>
```

It prints the Balanced profile/version, the semantic synthetic-audio frame, all 16 bands and the exact 44-byte Audio Sync V2 packet generated by the accepted encoder. CI builds it with warnings as errors and executes the `spin` preset as a smoke test.

## Automated evidence

WU-004 adds 13 native mapping tests on top of the accepted 31-test WU-001/002/003 baseline. They cover:

- profile and center-table stability;
- stationary level and stationary tilt silence;
- orientation shaping without false level;
- translation/rotation spectral distinction;
- shake versus slow-roll spectral distinction;
- one-shot tap/impact peak behavior;
- motion-to-stillness spectrum/peak clearing;
- finite/bounded output across every WU-003 trace family;
- major-peak centroid behavior;
- deterministic configurable mapping;
- byte-identical mapper→WU-001 encoder output for identical traces;
- invalid-snapshot peak safety.

The exact accepted CI run and merge SHA are recorded in the PR/roadmap after final documented-head verification.

## Evidence boundary

WU-004 automated evidence does **not** prove:

- perceptual quality across physical stock WLED effects;
- final QMI8658 noise/full-scale tuning;
- board-axis correctness;
- live packet cadence, multicast delivery or reconnect behavior;
- physical impact/tap thresholds;
- interoperability with a particular WLED release on real hardware.

Those require WU-005/WU-006 hardware and network evidence. WU-004 establishes deterministic semantics that can be tuned without changing motion extraction or packet encoding.
